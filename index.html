The problem

Running a hostel without a system shouldn't feel like this

A hostel is a hundred small transactions a day. On paper and WhatsApp, they slip — through notebooks, memory, and last-minute calls. This is what that actually looks like.

Rooms promised twice

Bookings live in notebooks and chat groups. By Friday, two residents think they own the same bed — and someone sleeps in the common room.

Cash with no paper trail

Payments get taken, notes get lost, and "I already paid" becomes an argument nobody can settle. Balances are whatever someone remembers.

Requests that vanish

A broken bulb is mentioned at the gate, scribbled on a scrap, or yelled across the office. Weeks later it's still flickering — and nobody knows who was supposed to fix it.

Visitors with no record

No log of who came in, when, or who they came to see. If something goes missing, there's no list to check — just a lot of "I don't know".

Numbers you can only guess

How full are we? What did we collect this month? The owner asks, and you reach for a calculator and an estimate you can't back up.

Data that dies with a laptop

Everything lives in one Excel file on one computer. A spill, a crash, a forgotten backup — and a whole term's records are gone.

Hardened headers

Frequently asked

How do I get started?

Reach out to us with your hostel details and we'll set up a personalized demo. You can also explore the system's features below and see how it works for teams like yours.

Which database does it use?

SQLite is used by default for development and local testing. For production deployments, PostgreSQL is supported and recommended. Migration scripts handle both databases automatically using Alembic.

Can I run more than one hall?

Yes — you can create multiple halls with their own room inventories, wardens, and occupancy statistics. The admin dashboard includes a hall comparison view showing occupancy percentage and revenue across all halls simultaneously.

How are payments handled?

All payments are recorded and fully auditable. The system supports partial payments through an installment system, automatically tracking balances against booking amounts. Every transaction is logged with timestamps, payment methods, and user references.

Is there an API?

Yes, the system includes a REST API v1 with OpenAPI 3.0 documentation. The API supports hall-scoped search operations, rate-limiting protection, and provides health monitoring endpoints. All API access is protected by the same authentication and authorization rules as the web application.

What are the costs?

Ostellos MS is self-hosted, so there are no licensing fees or per-user charges. You pay only for your hosting infrastructure and any third-party services you integrate (like email providers or payment gateways). Contact us for a tailored deployment quote.
